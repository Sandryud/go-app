# Exercises API

## Общие сведения

- **Базовый URL**: `http://localhost:8080`
- **Версия API**: `/api/v1`
- **Аутентификация**: обязательна — эндпоинты каталога упражнений доступны только авторизованным пользователям. В заголовке запроса: `Authorization: Bearer <access_token>`.

### Источник данных

Данные каталога хранятся в одном JSON-файле, который генерируется отдельным скриптом (`cmd/csv2json`) из CSV в директории `data/csv`. Результат сохраняется в файл, путь к которому задаётся в конфигурации приложения (по умолчанию `dist/exercises.json`). Переменная окружения `EXERCISES_CATALOG_PATH` позволяет переопределить путь к файлу.

Сервер не генерирует файл сам: он только читает уже существующий файл при каждом запросе. Обновление каталога выполняется отдельно (например, через `make exercises-json` или CI/CD).

### Формат ошибок

Ошибки возвращаются в едином формате API:

```json
{
  "error": {
    "code": "not_found",
    "message": "Exercises catalog not found",
    "details": null
  }
}
```

## Как работают методы

### Архитектура

Обработка запросов идёт по слоям:

1. **Handler** (`internal/handler/exercises`) — принимает HTTP-запрос, вызывает use case, формирует ответ (JSON, заголовки, статусы 200/304/404/500).
2. **UseCase** (`internal/usecase/exercises`) — тонкий слой: передаёт вызов в репозиторий без дополнительной логики.
3. **Repository** (`internal/repository/file`) — читает файл с диска, парсит из него версию из `meta.version` и при необходимости возвращает сырой JSON.

Версия каталога берётся из поля `meta.version` внутри JSON-файла (например, `"20260227102513"`). Она используется и в ответе эндпоинта версии, и как значение ETag для условных запросов к данным.

### Кэширование на клиенте (ETag)

Эндпоинт **GET /api/v1/exercises/data** поддерживает условные запросы по RFC 7232:

- В ответе **200** сервер всегда отдаёт заголовок **`ETag`** со значением текущей версии в кавычках (например, `ETag: "20260227102513"`).
- Клиент может сохранить этот ETag и при следующем запросе передать его в заголовке **`If-None-Match`**.
- Если переданный ETag совпадает с текущей версией каталога, сервер возвращает **304 Not Modified** без тела ответа — данные не изменились, клиент может использовать локальный кэш.
- Поддерживаются форматы `"version"` и `W/"version"`; при нескольких значениях в `If-None-Match` (через запятую) достаточно совпадения одного из них.

Так можно уменьшить трафик и нагрузку при частых проверках обновлений каталога.

## Эндпоинты

### GET `/api/v1/exercises/version`

- **Описание**: возвращает текущую версию каталога упражнений. Версия однозначно идентифицирует содержимое каталога (обычно это метка времени генерации в формате `YYYYMMDDHHMMSS`).
- **Назначение**: проверка, обновился ли каталог; сравнение с сохранённой на клиенте версией без загрузки полного файла.
- **Ответы**:
  - **200 OK** — версия успешно прочитана. Тело — JSON с полем `version`.

Пример ответа:

```json
{
  "version": "20260227102513"
}
```

- **401 Unauthorized** — отсутствует или невалиден JWT (истёк, неверная подпись и т.п.). Тело — стандартный формат ошибки.
- **500 Internal Server Error** — ошибка при чтении файла или определении версии (файл отсутствует, нет прав, некорректный JSON и т.п.). Тело — стандартный формат ошибки с кодом `internal_error`.

Пример запроса (с токеном):

```bash
curl -i -H "Authorization: Bearer <access_token>" http://localhost:8080/api/v1/exercises/version
```

---

### GET `/api/v1/exercises/data`

- **Описание**: отдаёт полный файл каталога упражнений в виде JSON. Структура: объект с полями `meta` (версия, дата генерации, количество записей) и `exercises` (массив упражнений).
- **Назначение**: первая загрузка каталога или обновление после того, как клиент узнал о новой версии через `/api/v1/exercises/version` или получил 200 (а не 304) при запросе с `If-None-Match`.
- **Заголовки запроса** (опционально):
  - **If-None-Match** — один или несколько ETag (например, `"20260227102513"` или `W/"20260227102513"`). Если один из них совпадает с текущей версией каталога, сервер вернёт 304 без тела.
- **Ответы**:
  - **200 OK** — каталог успешно прочитан. В заголовках: `Content-Type: application/json`, `ETag: "<version>"` (версия в кавычках). Тело — полный JSON каталога.
  - **304 Not Modified** — версия каталога не изменилась (значение `If-None-Match` совпало с текущей версией). Тело пустое; клиент может использовать закэшированные данные.
  - **401 Unauthorized** — отсутствует или невалиден JWT.
- **404 Not Found** — файл каталога не найден по сконфигурированному пути (например, скрипт генерации ещё не запускался). Тело — стандартный формат ошибки с кодом `not_found`.
- **500 Internal Server Error** — ошибка при чтении или разборе файла. Тело — стандартный формат ошибки с кодом `internal_error`.

Пример первого запроса (получение данных и ETag, с токеном):

```bash
curl -i -H "Authorization: Bearer <access_token>" http://localhost:8080/api/v1/exercises/data
```

Пример условного запроса (проверка без загрузки тела при совпадении версии):

```bash
curl -i -H "Authorization: Bearer <access_token>" -H 'If-None-Match: "20260227102513"' http://localhost:8080/api/v1/exercises/data
```

При неизменённом каталоге ответ будет с кодом **304** и пустым телом.

## Конфигурация

| Переменная окружения   | Описание                          | По умолчанию           |
|------------------------|-----------------------------------|------------------------|
| `EXERCISES_CATALOG_PATH` | Путь к файлу каталога упражнений | `dist/exercises.json` |

Путь задаётся относительно рабочей директории процесса сервера. Файл должен существовать и содержать валидный JSON с полем `meta.version`.
